# مغایرت‌گیر دامداران

برنامه اندرویدی مدیریت موجودی انبار و مغایرت‌گیری محصولات لبنی

<div dir="rtl">

## معرفی

«مغایرت‌گیر دامداران» یک اپلیکیشن اندرویدی کامل و حرفه‌ای برای مدیریت موجودی انبار و کنترل مغایرت محصولات لبنی است. این برنامه به‌صورت کامل آفلاین کار می‌کند و تمام اطلاعات روی دستگاه کاربر ذخیره می‌شوند.

این برنامه با تمرکز بر سه گروه محصول طراحی شده است:

- **استریل** (ظرفیت باکس ۲۷ عدد): شیر استریل ۲۰۰، شیر کاکائو استریل، خامه، شیر قهوه، شیر موز و ...
- **دبه** (ظرفیت باکس ۴ عدد): انواع ماست و دبه
- **خرما** (باکس رند): خرما و محصولات با بسته‌بندی رند

## ویژگی‌های اصلی

### ۱. محاسبات دقیق مغایرت

- محاسبه دقیق با عدد صحیح (بدون اعشار)
- پشتیبانی از تبدیل باکس و عدد
- نرمال‌سازی خودکار (مثلاً ۲ باکس و ۳۰ عدد → ۳ باکس و ۳ عدد برای محصول ۲۷ عددی)
- پشتیبانی از باکس رند
- جلوگیری از سرریز عددی

### ۲. مدیریت محصولات

- افزودن، ویرایش، فعال/غیرفعال‌سازی محصولات
- تعیین ظرفیت باکس برای هر محصول
- جست‌وجوی محصول
- جلوگیری از حذف محصول با سوابق (به‌جای آن، غیرفعال می‌شود)

### ۳. ثبت آمار روزانه

- ذخیره خودکار
- ادامه آمار نیمه‌تمام
- محاسبه زنده مغایرت
- نمایش همزمان باکس/عدد و تعداد کل
- نهایی‌سازی آمار با تأیید کاربر
- انتقال خودکار مانده پایان روز به روز بعد

### ۴. گزارش‌گیری

- گزارش روزانه همه محصولات
- فیلتر بر اساس نوع مغایرت (صفر، کسری، اضافه)
- خروجی PDF و CSV
- اشتراک‌گذاری فایل گزارش

### ۵. پشتیبان‌گیری

- ساخت فایل پشتیبان JSON
- بازیابی با تأیید کاربر
- اشتراک‌گذاری فایل پشتیبان

### ۶. رابط کاربری

- طراحی Material 3 مدرن
- راست‌چین فارسی
- فونت Vazirmatn
- پشتیبانی از تم روشن و تاریک
- انیمیشن‌های روان
- اعداد فارسی در نمایش

## قوانین محاسباتی

این قوانین مهم‌ترین بخش برنامه هستند:

### فرمول‌ها

1. **موجودی مورد انتظار پایان روز**:
   ```
   expectedClosingStock = openingStock + receipt - morningLoading - nightLoading - gifts - waste
   ```

2. **مغایرت پایان روز**:
   ```
   closingVariance = expectedClosingStock - currentStock
   ```

3. **مغایرت اول کار** (در صورت ورود مانده واقعی صبح):
   ```
   expectedMorningStock = openingStock - morningLoading
   morningVariance = expectedMorningStock - actualMorningStock
   ```

### تفسیر مغایرت

- **صفر**: موجودی مطابقت دارد
- **مثبت**: کسری (موجودی واقعی کمتر از مورد انتظار)
- **منفی**: اضافه (موجودی واقعی بیشتر از مورد انتظار)

### قوانین مهم

- رسید به موجودی **اضافه** می‌شود
- بارگیری صبح، بارگیری شب، هدایا و ضایعات از موجودی **کم** می‌شوند
- هیچ‌گاه هدایا یا ضایعات به موجودی اضافه نمی‌شوند
- تمام محاسبات با عدد صحیح انجام می‌شوند

## راهنمای نصب و ساخت APK

### پیش‌نیازها

- Android Studio Hedgehog (2023.1.1) یا بالاتر
- JDK 17
- Android SDK 34 (compileSdk)
- Gradle 8.5 (در پروژه گنجانده شده است)

### مراحل ساخت

1. **باز کردن پروژه در Android Studio**:
   - Android Studio را باز کنید
   - گزینه Open را انتخاب کنید
   - به پوشه `moghayerat-gir` بروید و آن را انتخاب کنید

2. **صبر برای Gradle Sync**:
   - Android Studio به‌صورت خودکار Gradle را همگام‌سازی می‌کند
   - در صورت نیاز به دانلود وابستگی‌ها، کمی صبر کنید

3. **افزودن فونت Vazirmatn** (اختیاری ولی توصیه می‌شود):
   - فایل‌های فونت Vazirmatn را از [گیت‌هاب رسمی](https://github.com/rastikerdar/vazirmatn) دانلود کنید
   - این فایل‌ها را در مسیر زیر قرار دهید:
     ```
     app/src/main/res/font/
     ├── vazirmatn_regular.ttf
     ├── vazirmatn_medium.ttf
     └── vazirmatn_bold.ttf
     ```
   - اگر این فایل‌ها را اضافه نکنید، از فونت پیش‌فرض سیستم استفاده می‌شود

4. **ساخت APK**:
   - از منوی Build → Build Bundle(s) / APK(s) → Build APK(s) را انتخاب کنید
   - پس از پایان ساخت، روی notification کلیک کنید تا APK نمایش داده شود
   - یا از مسیر زیر پیدا کنید:
     ```
     app/build/outputs/apk/debug/moghayerat-gir-debug-1.0.0.apk
     ```

5. **ساخت APK نهایی (Release)**:
   - برای ساخت نسخه نهایی، ابتدا یک keystore بسازید
   - از منوی Build → Generate Signed Bundle / APK را انتخاب کنید
   - مراحل ساخت keystore و امضای APK را طی کنید

### اجرای تست‌ها

برای اجرای تست‌های واحد:


یا از داخل Android Studio:
- روی پوشه `test` راست‌کلیک کنید
- گزینه Run Tests را انتخاب کنید

## راهنمای استفاده

### شروع سریع

1. **باز کردن برنامه**: برنامه را باز کنید. در صفحه اصلی، سه کارت برای انتخاب گروه محصول وجود دارد.

2. **انتخاب گروه**: روی گروه موردنظر (استریل، دبه یا خرما) کلیک کنید.

3. **انتخاب محصول**: از فهرست محصولات، محصول موردنظر را انتخاب کنید.

4. **ثبت آمار**: در صفحه ثبت آمار، مقادیر را در فیلدهای مربوطه وارد کنید. نتیجه مغایرت به‌صورت زنده محاسبه می‌شود.

5. **ذخیره یا نهایی‌سازی**: می‌توانید آمار را به‌صورت پیش‌نویس ذخیره کنید یا آن را نهایی کنید.

### توضیح فیلدها

| فیلد | توضیح |
|------|--------|
| مانده شب گذشته | موجودی باقی‌مانده از پایان روز قبل |
| بارگیری صبح | مقدار بارگیری شده برای توزیع یا شهرستان |
| مانده واقعی بعد از بارگیری صبح | (اختیاری) برای محاسبه مغایرت اول کار |
| رسید انبار | مقدار ورودی به انبار در طول روز |
| هدایا | مقدار خارج شده به‌عنوان هدیه |
| ضایعات | مقدار ضایعات |
| بارگیری شب | مقدار بارگیری شده در شب |
| مانده واقعی حال حاضر | موجودی شمارش‌شده در پایان روز |

### نکات مهم

- **ذخیره خودکار**: با خروج از صفحه ثبت آمار، اطلاعات به‌صورت خودکار ذخیره نمی‌شوند. حتماً روی «ذخیره پیش‌نویس» کلیک کنید.
- **نهایی‌سازی**: پس از نهایی‌سازی، برای ویرایش باید ابتدا نهایی‌سازی را لغو کنید.
- **انتقال مانده**: در روز جدید، برنامه به‌صورت خودکار مانده پایان روز قبل را به‌عنوان مانده شب گذشته پیشنهاد می‌دهد.
- **محصولات غیرفعال**: در صورت حذف محصولی که آمار دارد، محصول به‌جای حذف، غیرفعال می‌شود.

### گزارش‌گیری

- در صفحه گزارش‌ها، می‌توانید گزارش روزانه را به‌صورت PDF یا CSV دریافت کنید.
- می‌توانید گزارش را با دیگران به اشتراک بگذارید.
- فیلترهای مختلف برای مشاهده مغایرت‌های صفر، کسری یا اضافه وجود دارد.

### پشتیبان‌گیری

- در صفحه پشتیبان، می‌توانید یک فایل پشتیبان از تمام داده‌ها بسازید.
- می‌توانید این فایل را برای انتقال به دستگاه دیگر اشتراک بگذارید.
- برای بازیابی، فایل پشتیبان را انتخاب و تأیید کنید.

## تست‌های واحد

این پروژه شامل تست‌های واحد گسترده برای موتور محاسبات است که تمام ۱۲ سناریوی الزامی را پوشش می‌دهد:

1. مثال استریل ۲۰۰ با مغایرت صفر
2. کسری یک باکس (۲۷ عدد)
3. اضافه ۳ عدد
4. محاسبه رسید انبار
5. هدایا و ضایعات هم‌زمان
6. نرمال‌سازی ۲ باکس و ۳۰ عدد به ۳ باکس و ۳ عدد
7. جلوگیری از ثبت عدد برای باکس رند
8. بازسازی داده‌ها از مقادیر ذخیره‌شده
9. انتقال مانده پایان روز به روز بعد
10. ثبت صفر به‌عنوان مقدار معتبر
11. جلوگیری از سرریز محاسباتی
12. اصلاح اطلاعات و محاسبه مجدد
